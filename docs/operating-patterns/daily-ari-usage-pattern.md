# Daily ARI Usage Pattern

## Purpose

This document defines the canonical day-to-day operational usage pattern for ARI.

ARI should integrate into operational workflows continuously rather than acting as passive archival documentation.

---

# Daily Operational Loop

```text
Observe
-> Classify
-> Govern
-> Mutate
-> Validate
-> Reconcile
-> Preserve
```

---

# Step 1 — Observe

Operational changes, risks, drift, and runtime behavior become identified.

Examples:

- runtime mutation
- deployment
- schema change
- UX drift
- trust degradation
- operational incident

---

# Step 2 — Classify

The operational event becomes classified.

Examples:

- affected entities
- operational scope
- trust impact
- rollback complexity
- continuity risk

---

# Step 3 — Govern

Relevant governance primitives become attached.

Examples:

- contracts
- invariants
- trust boundaries
- runtime bindings
- lifecycle workflows

---

# Step 4 — Mutate

The operational mutation occurs.

Examples:

- deployment
- configuration change
- AI regeneration
- UX update
- orchestration change

---

# Step 5 — Validate

ARI evaluates:

- continuity preservation
- semantic alignment
- runtime projection alignment
- trust visibility
- lineage preservation

---

# Step 6 — Reconcile

If drift occurs:

- reconciliation
- rollback
- trust restoration
- runtime recovery

become evaluated.

---

# Step 7 — Preserve

Operational continuity becomes preserved through:

- graph updates
- event preservation
- snapshot preservation
- lineage preservation
- replay visibility

---

# Significance

This operational loop demonstrates how ARI becomes integrated into normal operational activity rather than functioning as passive documentation.
